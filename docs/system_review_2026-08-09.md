## 复核范围

本次复核覆盖教学配置、固定课表、摄像设备绑定、班级与课程权限、课次档案、课程分析、改进措施、课程报告、管理员演示分析与教师课后复盘页面。

## 结论

### 与研究背景的契合度

系统主定位已经从“教师上课时查看实时异常告警”调整为“课后基于录播或受控录像的教学复盘”。这一调整符合教师真实工作流：课表提供课次归属，分析结果形成可查证的事件材料，教师再完成观察、改进与验证记录。管理员保留的演示监控页面仅用于验证检测链路，不应作为论文或产品的核心教学使用场景。

### 功能一致性

1. 学年、学期、班级、课程、固定课表和摄像头—班级绑定能够为课次归属提供完整主数据。
2. “我的班级”按班级聚合，当前课程由获取时刻与固定课表匹配；进入课程报告仍以教学课程为数据与权限边界，避免同班不同课程混合。
3. 课次、事件、截图、VLM 复核、分析运行、课程条目、周期汇总、报告和改进措施的关系可追溯，适合毕业设计的系统实现与数据闭环描述。
4. 管理员拥有教学配置、设备绑定和全局档案入口；教师的课程分析权限由任课教师关系控制，班级级档案查看由班级授权控制。

## 已知限制与后续事项

| 优先级 | 事项 | 影响与建议 |
| --- | --- | --- |
| 高 | 课表调度器中“已结束课次”的状态转换缺少事务内持久化和专项自动化测试。 | 在修复事务边界并补充数据库集成测试前，不能将自动结束与待分析运行创建视为已验证能力。 |
| 中 | 真实录像离线分析执行器尚未接入。 | 当前 `SCHEDULED/PENDING` 只提供任务与数据结构基础；应在受控录像接入后实现读取、推理、失败重试与状态回写。 |
| 中 | 同一教师同班教授多门课程时，班级卡片统计会聚合多门课程，而详情页默认进入当前或默认课程。 | 当前业务假设“通常一位教师教授一门科目”时合理；若要支持多科常态化，应增加班级详情中的课程切换。 |
| 中 | 当前生成的教学课程未绑定任课教师。 | 这是“先不绑定教师”的测试数据要求带来的状态；教师账号的“我的班级”会为空。验证教师路径前，需要由管理员为课程分配任课教师。 |
| 中 | 测试以单元、构建和 API 冒烟为主。 | 应补充 MySQL 集成测试、课表跨时段测试、权限矩阵 E2E、真实录像样例和长稳测试。 |
| 低 | Docker 首次启动只自动执行 `001_init_mysql.sql`。 | 升级现有库必须按 README 手动执行 `002_teaching_analysis.sql`；生产部署应引入受控迁移流程。 |
